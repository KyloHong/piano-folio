# 部署计划：钢琴和弦图谱服务上线

## 1. 项目现状分析

### 技术栈
- **后端**: Node.js + Express，单文件 `server.js`
- **前端**: 单页 HTML (`index.html`)，通过 `express.static` 托管
- **数据库**: SQLite (`charts.db`，使用 `better-sqlite3`)
- **认证**: JWT (JSON Web Token)，7天过期
- **监听端口**: 3000

### 现有 API 路由
| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| POST | `/api/auth/register` | 注册 | 否 |
| POST | `/api/auth/login` | 登录 | 否 |
| GET | `/api/auth/me` | 当前用户信息 | 是 |
| GET | `/api/charts/my` | 我的图谱列表 | 是 |
| POST | `/api/charts/my` | 新建图谱 | 是 |
| PUT | `/api/charts/my/:id` | 更新图谱 | 是 |
| DELETE | `/api/charts/my/:id` | 删除图谱 | 是 |
| PUT | `/api/charts/my/:id/public` | 发布/取消发布 | 是 |
| GET | `/api/charts/public` | 公共图谱列表 | 否 |
| GET | `/api/charts/public/:id` | 公共图谱详情 | 否 |

### 当前安全风险（生产环境不可接受）
1. `JWT_SECRET` 使用硬编码默认值：`piano-chord-secret-key-2024`
2. `charts.db` 直接放在工作目录，无备份策略
3. 无进程管理，服务中断无法自动重启
4. 无 HTTPS，传输层无加密
5. 无 rate limiting，易受暴力破解攻击
6. `.gitignore` 未忽略 `charts.db`，生产数据库可能被覆盖

## 2. 部署方案

### 方案选择：Node.js + PM2 + Nginx（推荐）

适用于单台 VPS 部署，成熟稳定，维护简单。

**替代方案对比：**
- **纯 Docker**：隔离性好但需要 Docker 环境，端口映射稍复杂
- **云服务（Railway/Render/Heroku）**：零配置但有免费额度限制，数据库持久化需额外配置
- **当前推荐**：PM2 管理进程 + Nginx 反向代理，适合有 VPS 的场景

## 3. 具体实施步骤

### 步骤 1：准备服务器环境

```bash
# 安装 Node.js 18+ (如已安装跳过)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# 安装 PM2 (进程管理器)
sudo npm install -g pm2

# 安装 Nginx (反向代理)
sudo apt-get install -y nginx

# 安装 Certbot (Let's Encrypt HTTPS)
sudo apt-get install -y certbot python3-certbot-nginx
```

### 步骤 2：上传项目到服务器

```bash
# 在本地打包（排除 node_modules 和 charts.db）
cd /workspace
npm install  # 安装依赖

# 上传到服务器 /var/www/piano-folio/
scp -r server.js package.json package-lock.json index.html charts_data.md user@your-server:/var/www/piano-folio/

# 在服务器安装依赖
cd /var/www/piano-folio/
npm install --production
```

### 步骤 3：配置环境变量

创建 `/var/www/piano-folio/.env`：

```env
PORT=3000
NODE_ENV=production
JWT_SECRET=<生成256位随机字符串>
```

生成安全密钥：
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

### 步骤 4：更新 server.js 使用环境变量

修改 `/workspace/server.js` 第 13 行：

```javascript
// 修改前
const JWT_SECRET = process.env.JWT_SECRET || 'piano-chord-secret-key-2024';

// 修改后
const JWT_SECRET = process.env.JWT_SECRET;
if (!JWT_SECRET) {
    console.error('❌ JWT_SECRET 环境变量未设置');
    process.exit(1);
}
```

### 步骤 5：使用 PM2 启动服务

创建 ecosystem 配置文件 `/var/www/piano-folio/ecosystem.config.js`：

```javascript
module.exports = {
  apps: [{
    name: 'piano-folio',
    script: 'server.js',
    env: {
      NODE_ENV: 'production',
      PORT: 3000
    },
    instances: 1,
    autorestart: true,
    max_memory_restart: '500M',
    error_file: '/var/log/piano-folio/error.log',
    out_file: '/var/log/piano-folio/out.log',
    log_date_format: 'YYYY-MM-DD HH:mm:ss'
  }]
};
```

启动并设置开机自启：
```bash
sudo mkdir -p /var/log/piano-folio
cd /var/www/piano-folio
pm2 start ecosystem.config.js
pm2 save
pm2 startup  # 按提示执行生成的命令设置开机自启
```

### 步骤 6：配置 Nginx 反向代理

创建 `/etc/nginx/sites-available/piano-folio`：

```nginx
server {
    listen 80;
    server_name your-domain.com;  # 替换为你的域名

    # 强制跳转到 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl;
    server_name your-domain.com;  # 替换为你的域名

    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    client_max_body_size 10M;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;

        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # 静态资源缓存
    location ~* \.(html|js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        proxy_pass http://127.0.0.1:3000;
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # API 请求不缓存
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        no-cache;
    }
}
```

启用站点：
```bash
sudo ln -s /etc/nginx/sites-available/piano-folio /etc/nginx/sites-enabled/
sudo nginx -t  # 测试配置
sudo systemctl reload nginx
```

## 4. 安全加固（可选但强烈建议）

### 4.1 登录限流

在 `server.js` 中添加简单的内存限流（防止暴力破解）：

```javascript
const loginAttempts = new Map();

function rateLimit(key, maxAttempts = 5, windowMs = 15 * 60 * 1000) {
    const now = Date.now();
    const record = loginAttempts.get(key) || { count: 0, resetAt: now + windowMs };
    if (now > record.resetAt) {
        record.count = 0;
        record.resetAt = now + windowMs;
    }
    record.count++;
    loginAttempts.set(key, record);
    return record.count <= maxAttempts;
}
```

在登录接口中使用：
```javascript
const clientIp = req.ip || req.connection.remoteAddress;
if (!rateLimit(clientIp)) {
    return res.status(429).json({ error: '登录尝试过于频繁，请15分钟后再试' });
}
```

### 4.2 CORS 配置（当前为开发环境配置）

生产环境应限制允许的域名：

```javascript
// 当前配置（不安全）
app.use(cors());

// 建议改为
app.use(cors({
    origin: process.env.ALLOWED_ORIGINS?.split(',') || 'https://your-domain.com'
}));
```

## 5. 数据库备份策略

### 自动备份脚本 `/root/backup-db.sh`

```bash
#!/bin/bash
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR=/var/backups/piano-folio
mkdir -p $BACKUP_DIR
cp /var/www/piano-folio/charts.db $BACKUP_DIR/charts_$DATE.db
# 保留最近30个备份
ls -t $BACKUP_DIR/charts_*.db | tail -n +31 | xargs -r rm
```

设置定时任务：
```bash
crontab -e
# 每天凌晨3点备份
0 3 * * * /root/backup-db.sh >> /var/log/backup-db.log 2>&1
```

## 9. 假设与决策

1. **假设用户有一台可用的 VPS**（Linux），拥有 root 或 sudo 权限
2. **假设用户有可用的域名**，或使用 IP 直接访问（域名更推荐用于 HTTPS）
3. **选择 PM2 + Nginx 而非 Docker**，因为当前项目为单文件服务，架构简单，PM2+Nginx 足够且更轻量
4. **数据库选择 SQLite**，适合中小流量（万级用户以内），无需额外数据库服务
5. **JWT_SECRET 必须设置**，生产环境不再使用硬编码默认值
6. **暂不修改前端代码**，`index.html` 已在本地验证通过的功能保持不变
